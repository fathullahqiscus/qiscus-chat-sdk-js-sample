# PWA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the static chat sample installable and provide an offline public shell after one successful online visit.

**Architecture:** A native, versioned service worker precaches a strictly allowlisted public shell and uses network-first navigation with a cached shell fallback. The browser UI receives connectivity state through an AMD service; user data and all SDK/API traffic remain network-only.

**Tech Stack:** Static HTML, RequireJS AMD, vanilla JavaScript, CSS, Web App Manifest, Service Worker, Node built-in test runner.

**Spec:** `docs/superpowers/specs/2026-09-14-pwa-design.md`

## Global Constraints

- Do not cache authenticated API responses, messages, attachments, remote avatars, tokens, credentials, or the JWT endpoint.
- Preserve URL parsing for `appId`, `baseUrl`, and `brokerUrl`; installed launch intentionally uses only saved App ID.
- Do not add a build system, offline message queue, push, or forced reload during an update.
- Cache only reviewed public shell URLs; cache cleanup must only affect `qiscus-pwa-shell-*` names.
